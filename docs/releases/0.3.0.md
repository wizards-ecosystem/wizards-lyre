# The Wizard's Lyre 0.3.0

Lyre still runs ACE-Step 1.5 on your own GPU. This release makes the
studio you already have dependable, rather than adding features. What you
asked for is what renders. A job survives a reload or a crash. A take records
exactly how it was made. Agents get the same rules through `/v1` and MCP.

## Install or update

Stop the server and the worker. Download `wizards-lyre-0.3.0-linux-x86_64.tar.gz`
or the matching `.zip`, plus `SHA256SUMS`, from the assets below. Verify it,
extract it into a **new** directory, and install:

```bash
sha256sum --ignore-missing --check SHA256SUMS
./scripts/lyre install
```

Copy `projects/` from your 0.2.0 directory into the new one, then start
Lyre there. The first start migrates the copy. Keep the 0.2.0 directory
until 0.3.0 opens your library: it is your way back. From now on,
`./scripts/lyre backup` makes a checked backup.

Projects from 0.2.0 open unchanged; the database migration is additive.
A job that was still queued when you upgraded has no snapshot of what to
render, so it waits as "Needs confirmation". Choose Retry or Cancel. A
downgrade is not supported; go back to the 0.2.0 directory instead. See
[COMPLETION_MIGRATION.md](../COMPLETION_MIGRATION.md).

## Highlights

- **What you write wins.** Start from an idea or from a brief. Every field
  shows where its value came from (you, the planner, a preset, or a
  default), and the planner never overwrites a field you set. Captions are
  not rewritten unless you ask. Lyrics you supply are sung verbatim.
- **Jobs survive.** Each job freezes what it will render when you submit
  it. Renders are committed atomically, so a crash never leaves half a take.
  The studio reattaches to running jobs after a reload. A finished take
  never replaces the one you kept.
- **Safe edits.** Plan saves are revisioned. If another tab or an agent
  saved first, you choose "Keep my edits" or "Use saved plan", and a local
  draft keeps your text in the meantime.
- **Provenance.** Each take records its job, the resolved brief, the actual
  parameters, stage timings, and the runtime. The export ZIP carries
  `manifest.json`.
- **Readiness and presets.** The studio and `GET /v1/capabilities` say what
  this machine can render now. Six curated presets cover songs and game cues.
- **Audition.** One player owns playback. A/B switching keeps the position,
  and Space plays and pauses outside text fields.
- **Agents.** `/v1` (one-shot songs, plan writes, idempotent POSTs, retry)
  and an MCP server (`./scripts/lyre mcp`) with `get_capabilities`,
  `generate_take`, `set_active_take`, and `get_export` alongside the existing
  tools. Opt-in API keys for a non-loopback bind.

See the [0.3.0 changelog](https://github.com/wizards-ecosystem/wizards-lyre/blob/v0.3.0/CHANGELOG.md).

## Known limitations

- A fixed seed reproduces audio only with language-model codes off. Planned
  briefs use them, and upstream's sampling is not reproducible from the seed.
- Lyre needs about 10-11.7 GB of free VRAM with the LM loaded. On a shared
  GPU with less headroom, ACE-Step refuses a render before it starts, and
  the job says so.
- Planning a song takes about 10 s, and switching into the `quality`
  profile about 23 s, on the machine above.
- SSE, webhooks, and signed artifact tokens (SPEC.md section 15) are not
  served yet. `/api` does not send deprecation headers yet.

## Remote GPU

The host image for this release is built, booted, attested, and pushed by
the **Remote GPU image** workflow when the release is published. This
release fixes two image problems: a host built after the MP3 change could
not start, and `server/generation` was left out of the build context. The
Remote GPU lane was not re-verified live on a rented pod for this release.

## Supported boundary

- The Lyre server binds only to `127.0.0.1` with no authentication unless
  you opt in to API keys.
- Everything in the [0.2.0 supported boundary](0.2.0.md#supported-boundary)
  still applies.
